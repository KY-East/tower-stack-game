## 文档说明

### 1. 代码参考

`code/`目录中的文件**仅作为参考**，不可直接在新项目中使用。这些代码存在以下问题：

- 包含多处bug和运行错误
- 可能与新项目的架构不兼容
- 部分功能实现不完整或有逻辑问题

**正确使用方式**：

1. 仅作为实现思路的参考
2. 根据新项目需求重新编写代码
3. 避免直接复制粘贴，而应理解核心逻辑后进行改进

### 2. 文档参考

`docs/`目录中的文件提供了设计思路和概念，可以作为新项目开发的参考。这些文档包括：

- 项目架构设计思路
- 核心功能实现方案建议
- 视觉设计概念
- 反馈系统设计思路
- 预言系统工作机制构想

### 3. 主要设计理念

与旧项目相比，新项目应考虑以下改进方向：

1. **界面语言**：所有用户可见文本改为英文
2. **判定系统**：简化为"完美"和"一般"两种判定
3. **主题调整**：专注于希腊风格的一致性
4. **代码优化**：解决旧项目中的兼容性和bug问题

### 4. 项目升级建议

1. **保持原有结构**：在现有代码基础上进行渐进式修改，保持原有的项目结构和路径
2. **逐步改造**：一次只专注于一个方面的改进，完成后再进行下一个
3. **建立变更日志**：记录每次修改的内容，方便追踪变更历史
4. **保持兼容性**：确保每次修改后游戏仍能正常运行
5. **测试验证**：每次改动后进行测试，确保功能正常

## 注意事项

- 本文档中的代码**仅作为参考思路**，实际修改时应确保与原有代码的兼容性
- 视觉资源(图像、音频等)需要另行准备
- 修改过程应进行持续测试，确保每一步改动后游戏都能正常运行

## 兼容性检查

项目升级应重点关注以下方面：

- 现代浏览器(Chrome, Firefox, Safari, Edge)的兼容性测试
- 响应式设计的完整实现
- 基本的性能优化
- 避免内存泄漏问题
