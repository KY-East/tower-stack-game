# 希腊叠塔游戏 - 开发指南

本文档为希腊叠塔游戏的开发团队提供详细的开发流程、代码规范和最佳实践指导。

## 开发环境搭建

### 必要软件

- **Node.js** (v14+)
- **npm** (v6+)
- **Git** (最新版)
- **现代浏览器** (Chrome/Firefox/Edge最新版)
- **编辑器** (推荐Visual Studio Code)

### 项目初始化

1. 克隆仓库：
```bash
git clone <repository-url>
cd greek-tower
```

2. 安装依赖：
```bash
npm install
```

3. 启动开发服务器：
```bash
npm run dev
```

4. 构建生产版本：
```bash
npm run build
```

## 项目结构

详细的项目结构请参考 [项目结构设计](./project_structure.md) 文档。开发者应熟悉项目的模块划分和各组件职责。

## 开发流程

### 分支管理

- `main`: 稳定分支，只接受经过充分测试的合并请求
- `develop`: 开发主分支，功能完成后合并到此分支
- `feature/xxx`: 功能开发分支，从develop分支创建
- `bugfix/xxx`: 错误修复分支，从develop分支创建
- `hotfix/xxx`: 紧急修复分支，从main分支创建

### 开发步骤

1. **需求分析**：理解功能需求，确定实现方案
2. **创建分支**：从develop分支创建新的功能分支
3. **编码实现**：按照规范编写代码
4. **本地测试**：确保功能正常，没有明显bug
5. **提交代码**：编写清晰的提交信息
6. **代码评审**：请求其他开发者审查代码
7. **合并代码**：解决所有评审意见后合并到develop分支
8. **集成测试**：在develop分支上进行集成测试
9. **发布计划**：根据开发进度安排发布

## 代码规范

### JavaScript规范

- 使用ES6+语法和特性
- 使用严格模式 `'use strict';`
- 使用`const`和`let`替代`var`
- 类名使用PascalCase (如`BlockRenderer`)
- 方法和变量名使用camelCase (如`createBlock`)
- 常量使用UPPER_CASE (如`MAX_BLOCKS`)
- 使用JSDoc风格的注释

```javascript
/**
 * 创建一个希腊风格的方块
 * @param {number} width - 方块宽度
 * @param {number} height - 方块高度
 * @param {Object} options - 配置选项
 * @returns {Object} 创建的方块对象
 */
function createGreekBlock(width, height, options = {}) {
  // 实现代码
}
```

### 文件组织

- 每个模块放在单独的文件中
- 相关功能组织在同一目录下
- 文件名使用小写，多词使用连字符分隔 (如`block-renderer.js`)
- 导入模块时按照以下顺序组织:
  1. 核心模块和第三方库
  2. 项目内部共享模块
  3. 当前目录的模块

```javascript
// 第三方库
import * as THREE from 'three';
import { TweenLite } from 'gsap';

// 项目内部模块
import { config } from '../config';
import { logger } from '../utils/logger';

// 当前目录模块
import { createMaterial } from './materials';
```

### 代码风格

- 缩进使用2个空格
- 语句末尾使用分号
- 运算符周围添加空格
- 代码块使用大括号，即使只有一行
- 字符串优先使用单引号
- 避免行尾空格
- 文件末尾保留一个空行

### 注释规范

- 为所有公共API提供JSDoc注释
- 复杂逻辑添加必要的解释性注释
- 使用`// TODO:`标记待完成的事项
- 使用`// FIXME:`标记需要修复的问题
- 代码提交前移除调试打印和注释掉的代码

## 性能优化

### 渲染优化

- 减少不必要的几何体创建
- 合理使用材质和纹理
- 避免每帧重新计算不变的值
- 使用对象池减少内存分配和GC压力
- 利用Three.js的性能优化技术

### 资源加载

- 使用异步加载非关键资源
- 合并和压缩纹理图集
- 优化模型和纹理大小
- 实现资源预加载
- 添加加载进度反馈

## 测试策略

### 单元测试

- 为核心逻辑编写单元测试
- 模拟依赖进行隔离测试
- 测试边界条件和异常情况

### 功能测试

- 测试游戏核心功能
- 验证游戏状态转换
- 检查游戏规则实现

### 性能测试

- 监控帧率和内存使用
- 测试不同设备的性能表现
- 识别并优化性能瓶颈

### 兼容性测试

- 在主流浏览器上测试
- 验证移动设备兼容性
- 测试不同屏幕尺寸适配

## 调试技巧

### 开发工具

- 使用Chrome DevTools的Performance面板分析性能
- 使用Memory面板检测内存泄漏
- 启用Three.js Inspector插件调试场景

### 常见问题排查

- 性能下降：检查渲染循环、对象创建和垃圾回收
- 游戏逻辑问题：添加状态日志，追踪状态变化
- 渲染错误：检查场景图、相机设置和着色器

### 日志和监控

- 在开发模式启用详细日志
- 使用性能监控面板
- 实现远程错误报告机制

## 游戏组件开发指南

### Game 组件开发

- 保持游戏逻辑与渲染分离
- 实现清晰的游戏状态管理
- 使用事件系统进行组件间通信

### Block 组件开发

- 设计合理的方块数据结构
- 优化碰撞检测算法
- 实现平滑的移动和堆叠逻辑

### Oracle 预言系统开发

- 设计灵活的消息触发机制
- 创建多样化的预言内容
- 实现吸引人的文本显示效果

- 确保效果增强游戏体验而不干扰游戏性

### 音频系统开发

- 实现响应式音频播放
- 处理浏览器音频播放限制
- 优化音频资源加载和管理

## 版本发布流程

### 版本规划

- 遵循语义化版本 (SemVer) 规范
- 明确每个版本的功能范围
- 创建详细的里程碑计划

### 发布检查清单

- 所有功能测试通过
- 性能达到预期目标
- 兼容性测试无明显问题
- 代码已经过评审
- 文档已更新

### 部署流程

1. 从develop分支创建release分支
2. 执行最终测试和修复
3. 更新版本号和更新日志
4. 合并到main分支并打标签
5. 构建生产版本
6. 部署到生产环境
7. 将更改合并回develop分支
